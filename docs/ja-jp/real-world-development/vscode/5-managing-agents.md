GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。作業は手元のマシンでリアルタイムに進むため、VS Code の Copilot Chat ではツールの呼び出しやファイルの編集を逐一確認できます。差分をインラインでレビューし、個々の変更を採用または却下できます。また、エディターを離れずに追加のプロンプトを送って会話を調整したり、作業を広げたりできます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして採用します。
- 進行中のセッションでエージェントに指示し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson] で使ったアクセシビリティのカスタム エージェントが、ハイ コントラスト モードを実装しています。作業中、デザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードも切り替えられるようにしたいとのことです。最初から新しい会話を始めるのではなく、既存のセッションに指示を追加して作業を広げます。

## Copilot の進行状況を監視する

Copilot Chat ビューでは、エージェントが実行する各手順を確認できます。調べているファイル、実行するコマンド、提案する編集が表示されます。ファイルの編集は差分と **Keep** / **Undo** のコントロールとともに、チャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると、変更を採用します。
   - **Undo** を選択すると、変更を元に戻して、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などでツールが許可を求めると、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドのみを許可してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライト モードの追加を依頼する

ハイ コントラスト モードができたので、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けるため、エージェントはこれまでの作業、変更したコンポーネント、使用したスタイル、設定した local storage のパターンを引き続き利用できます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライト モード用の更新を提案します。
3. ハイ コントラストのときと同じように、新しい編集を確認します。各差分で **Keep** または **Undo** を選択します。
4. たとえば、エージェントが希望しない方向で作業を進めた場合 (好みではない方法でトグル UI をリファクタリングするなど)、チャット入力欄の横にある **Stop** ボタンで停止させてから、追加の説明を送ります。

> [!TIP]
> 作業中のセッションに指示するほうが、最初からやり直すより短時間で済みます。追加プロンプトを使って、調整を依頼できます (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」など)、方向を修正できます (「3 つ目のトグルを追加せず、ライト モードを既存の設定パネルに組み込む」など)、作業範囲を広げることもできます (「両方のトグルにキーボード ショートカットも追加する」など)。

## 作業セットをレビューする

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧をすべて確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による保存など、カスタム エージェントが適用したアクセシビリティのパターンを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat agent mode を使い、作業中のセッションを監視して指示しました。ファイルの編集を確認し、変更を採用または却下し、会話のコンテキストを保ったまま追加のプロンプトを送って作業を広げました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または却下しました。
- 進行中のセッションに追加のプロンプトを送って作業を調整しました。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通じてローカルのカスタム エージェントが作成した変更をレビューします。
